# Offline My Library, automatic retention and streaming cache

The Kotlin core owns retention, scheduling order, local playability, validation, storage limits and
LRU decisions. Native shells own settings presentation and the operating system's file/network and
playback services. Cache identity uses the same account/server instance, raw item and profile tuple
as downloads. A durable normalized endpoint URL/username binding additionally owns that namespace; a rebind purges old media before the new binding can resolve a local file.

## Retry after observed server loss

A local retry does not establish that the server returned. The common queue admits a guarded,
explicit retry of its selected current item without changing the predicate used by other entries.
Native start still validates the local file before using it. If that file is missing, a deliberate
remote fallback requires OS connectivity and configured account contact. Only accepted progress
from the matching current remote attempt restores playback reachability; resolving a URL or
starting a local file does not.

## Account rebinding and removal recovery (2026-10-20)

A genuinely different canonical endpoint or exact username under the same provider instance purges prior automatic, explicit and
cached media. Equivalent URL spellings and password-only refresh preserve it. This is a separate boundary from removing music
from My Library or disabling Automatic Downloads: those same-binding operations still preserve
explicit downloads. The binding is a reserved durable preference outside the disposable seen-cache
namespace. An epoch revokes old controllers and in-flight callbacks even across A → B → A. Legacy
media with no provable binding is purged rather than adopted. Startup establishes both media and
metadata binding before automatic membership projection.

The Android service also retires its player and session if saved credentials cannot be read:
the plaintext account ID cannot prove that the endpoint and username are unchanged. This stops
playback on a credential-read failure without purging files. Readable recovery creates a fresh
controller; same-binding media remains valid. Password refresh updates future request credentials while retaining installed playback, preloads and media.
